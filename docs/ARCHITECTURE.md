# Архитектура

## Принципы

1. **Local-first:** обработка идёт на устройстве пользователя.
2. **Evidence-first:** вывод без ссылки на реплику удаляется.
3. **Graceful failure:** пользователь получает конкретную причину ошибки модели.
4. **Последовательная загрузка:** тяжёлые модели не обязаны одновременно занимать GPU.
5. **Минимум инфраструктуры:** один FastAPI-процесс, статический интерфейс и Ollama.

## Поток данных

| Этап | Вход | Выход | Компонент |
| --- | --- | --- | --- |
| Нормализация | MP3/WAV/M4A | WAV, mono, 16 kHz | FFmpeg |
| ASR | WAV | текстовые сегменты и таймкоды | Faster-Whisper |
| Диаризация | WAV | интервалы голосов | pyannote Community-1 |
| Выравнивание | два набора интервалов | реплики со спикерами | Python |
| Анализ | реплики с ID | строгий MeetingReport JSON | Ollama + Qwen3 |
| Валидация | MeetingReport | только подтверждённые элементы | Pydantic + evidence filter |
| Вывод | MeetingResult | UI, JSON, CSV, PDF | FastAPI + ReportLab |

## Главный контракт данных

Каждая реплика получает стабильный ID:

```json
{
  "id": "seg_0007",
  "start": 34.2,
  "end": 39.7,
  "speaker": "Speaker 2",
  "text": "Я подготовлю расчёты к пятнице."
}
```

Каждый вывод LLM обязан ссылаться на него:

```json
{
  "owner": "Speaker 2",
  "task": "Подготовить расчёты",
  "due_date": "пятница",
  "priority": "not_specified",
  "evidence": ["seg_0007"]
}
```

Если `evidence` пуст или содержит несуществующие IDs, вывод удаляется до показа.

## Локальность

В рабочем режиме разрешены только обращения к `127.0.0.1`, где запущен Ollama.
Модели скачиваются заранее и лежат в `models/` или в локальном хранилище Ollama.
Папки `models/` и `data/` исключены из Git.
